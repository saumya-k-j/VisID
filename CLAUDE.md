# CLAUDE.md — context for working on VisID with Claude Code

## What this repo answers
Do semantic IDs built from product images (or images fused with text) improve generative
retrieval for cold-start items, and what does generative retrieval cost at inference time
versus FAISS ANN retrieval? Either answer is fine; an unexplained answer is not.

## Module boundaries (do not blur them)
| Package | Owns | Must not |
|---|---|---|
| `visid/data/` | raw loading, k-core, chronological sequences, leave-one-out + cold split, image check/download, synthetic data | touch models |
| `visid/ids/` | content encoders, PCA to common dim, RQ-VAE, collision token, prefix trie | know about users |
| `visid/models/` | SASRec / two-tower (`sasrec.py`), TIGER (`tiger.py`), beam search (`decoding.py`), training loops (`train.py`) | compute metrics by hand |
| `visid/eval/` | metrics, warm/cold breakdown, coverage, why-diagnostics (`analysis.py`) | train anything |
| `visid/bench/` | latency sweeps and the recall-vs-latency plot | change model behaviour |
| `visid/cli.py` | the only place that knows file paths and wires stages together | contain modelling logic |

## Invariants (tests enforce these; keep it that way)
- Item ids are 1-based; **row 0 is padding** in every per-item array (embeddings, ID tables).
- ID table: `int64 [num_items + 1, 4]`, row 0 = -1; level sizes `[256, 256, 256, max_group]`.
- The split is fixed by `data.split_seed`; model seeds never change it.
- Cold items get **no training signal**: not in any history, not a target, and excluded from
  the softmax / negative pool (`exclude_items`). Test: `test_cold_items_get_no_training_signal`.
- Every model ranks the **full catalog** (warm + cold); history items are not masked.
- Constrained decoding only returns catalog IDs (`test_trie_decoding.py`).
- Every reported number is regenerated by a CLI command; never edit tables by hand.

## Commands
```bash
make test                         # spec tests, ~10 s
make smoke                        # entire pipeline on synthetic data, ~8 min CPU
make all C=configs/beauty2014.yaml          # the study
python -m visid.cli <cmd> --config <cfg> --seed 0 --set tiger.epochs=10   # any stage, with overrides
```
Outputs: `data/processed/<data>/`, `data/embeddings/<data>/`, `data/ids/<data>/<variant>/seed<k>/`,
`results/<data>/<exp>/seed<k>/{config.yaml,train_log.jsonl,metrics.json}`, `results/<data>/table.md`.

## Working rules
1. Write or extend the spec test first (from the behaviour you want), watch it fail, then implement.
2. Hand-compute expected values in metric tests; do not derive them from the code under test.
3. When AI-generated code is wrong and a test or diagnostic catches it, add an entry to
   `docs/ai_error_log.md` (what was wrong, what caught it, the fix, the test that now guards it).
4. Configs are the experiment record. New knob → add it to `configs/base.yaml` with a comment.
5. Do not report numbers from `configs/smoke.yaml`; they are plumbing checks.
